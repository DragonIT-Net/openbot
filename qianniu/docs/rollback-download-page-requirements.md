# 历史版本安装包管理页面（需求说明，供后端实现）

## 背景

客户端（千牛智能插件）新增了自动更新机制（见 [ADR 0005](adr/0005-update-mechanism.md)）：正常升级到新版本是全自动的，客服人员不需要手动下载任何文件。

但如果新版本上线后发现问题，需要让某个客服"回退到某个旧版本"，这次不打算在客户端做"应用内一键回退"的功能，而是做一个**后端管理页面**，人工介入完成回退。

## 需要的功能

1. **上传安装包**：管理员能上传一个新版本的安装包文件（`.exe`，Inno Setup 生成的静默安装包，可能有几十 MB），录入对应的版本号（跟客户端 `Params.Version` 同一套格式，字符串形式 `v9.5.3`——注意不补零，`Params.Version=90503` 换算出来就是 `v9.5.3` 不是 `v9.05.03`）和版本说明（可选的一段文字）。
2. **版本列表**：展示已经上传过的所有历史版本（版本号、上传时间、版本说明、下载次数可选），按版本号或上传时间排序。
3. **客服人员下载**：客服人员能打开这个页面，看到版本列表，选择某一个历史版本，点击下载得到对应的安装包文件——下载下来之后是客服自己手动双击运行安装（走正常的 Inno Setup 静默/非静默安装流程都行，不需要客户端配合）。
4. **权限**：这个页面理论上面向内部客服/管理员，具体要不要登录鉴权、跟现有的钉钉登录（如果已经上线）打通，由你们后端团队决定，不是这份文档要限定的范围。

## 跟自动更新接口的关系

客户端自动更新用的 `GET /update/latest` 接口（见 [plan.md](../plan.md) 第 1 节）只返回**最新版本**这一条记录。这个管理页面背后维护的"版本列表"，理论上应该是 `/update/latest` 数据的一个超集（最新版本 + 所有历史版本），具体是不是同一张表、要不要复用同一套上传流程来同时更新"最新版本"记录，由后端自行设计，客户端不关心实现细节。

## 明确不需要做的部分

- 不需要客户端能列出历史版本、不需要客户端内嵌"选择版本回退"的界面或逻辑。
- 不需要自动检测"当前版本有问题，自动建议回退"这类智能能力，回退始终是人工判断后手动触发的操作。
